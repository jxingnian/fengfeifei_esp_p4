## 📋 架构概述

本次重构将项目从"功能堆叠"模式升级为**分层架构**，实现了统一的设备状态管理、资源调度和业务扩展能力。


## 🔄 设备状态机设计

### 状态定义

```
启动阶段：
├─ BOOT                    // 设备启动
├─ NETWORK_CONNECTING      // 网络连接中
└─ SERVICE_STARTING        // 后台服务启动中

运行阶段：
├─ IDLE                    // 待机（唤醒词监听）
├─ AI_STARTING             // AI对话启动中
├─ AI_LISTENING            // AI监听用户
├─ AI_PROCESSING           // AI处理中（等待回复）
├─ AI_PLAYING              // AI播放回复
├─ VOICE_CALL_INCOMING     // 语音来电振铃
├─ VOICE_CALL_ACTIVE       // 语音通话中
├─ VIDEO_CALL_INCOMING     // 视频来电振铃
├─ VIDEO_CALL_ACTIVE       // 视频通话中
└─ ERROR_RECOVERY          // 错误恢复中
```

### 事件定义

```c
// 网络事件
EVENT_WIFI_CONNECTED         // Wi-Fi连接成功
EVENT_NETWORK_READY          // 获取IP地址
EVENT_NETWORK_LOST           // 网络断开

// 服务事件
EVENT_BACKEND_CONNECTED      // 后台连接成功
EVENT_COZE_READY            // Coze服务就绪
EVENT_SERVICE_READY         // 所有服务就绪
EVENT_BACKEND_DISCONNECTED  // 后台断开

// AI对话事件
EVENT_WAKE_WORD_DETECTED    // 检测到唤醒词
EVENT_AI_READY              // AI服务就绪
EVENT_USER_SPEAKING         // 用户开始说话
EVENT_USER_STOPPED          // 用户停止说话
EVENT_AI_REPLY_START        // AI开始回复
EVENT_AI_REPLY_END          // AI回复结束
EVENT_CONVERSATION_ENDED    // 对话结束
EVENT_CONVERSATION_TIMEOUT  // 对话超时

// 通话事件
EVENT_INCOMING_VOICE_CALL   // 语音来电
EVENT_INCOMING_VIDEO_CALL   // 视频来电
EVENT_CALL_ACCEPTED         // 接听电话
EVENT_CALL_REJECTED         // 拒接电话
EVENT_CALL_ENDED            // 通话结束
EVENT_USER_HANGUP           // 用户挂断

// 错误事件
EVENT_AUDIO_ERROR           // 音频错误
EVENT_COZE_ERROR           // Coze服务错误
EVENT_RECOVERY_COMPLETE    // 恢复完成
```

### 优先级规则

```
通话 > AI对话 > 待机

规则1：通话状态拒绝唤醒词
  VOICE_CALL_ACTIVE + EVENT_WAKE_WORD → 忽略事件

规则2：AI对话中来电立即打断
  AI_LISTENING + EVENT_INCOMING_VOICE_CALL 
    → 先停止AI对话
    → 再进入通话状态

规则3：通话结束恢复待机
  VOICE_CALL_ACTIVE + EVENT_CALL_ENDED
    → 清理通话资源
    → 转换到IDLE（恢复唤醒词监听）

规则4：网络断开强制错误恢复
  任何状态 + EVENT_NETWORK_LOST
    → 清理当前业务
    → 转换到ERROR_RECOVERY
```

## 🎯 关键架构调整

### 1. Coze连接生命周期分离

**❌ 旧方式（错误）：**
```
唤醒词 → 建立Coze连接 → 对话 → 断开连接
```

**✅ 新方式（正确）：**
```
启动阶段：
  Wi-Fi连接 → 后台服务连接 → Coze服务连接（保持）

唤醒后：
  开始会话轮次 → 对话 → 结束轮次
  （Coze连接保持，不断开）

网络断开时：
  自动重连Coze服务
```

**代码变更：**
- `coze_app_connect()`: 启动时建立WebSocket连接（长连接）
- `coze_app_begin_turn()`: 唤醒时开始新一轮对话
- `coze_app_end_turn()`: 对话结束时结束轮次
- `coze_app_reconnect()`: 网络恢复后重连

### 2. 音频资源统一调度

**❌ 旧方式：**
```
wake_word 和 ai_dialog 直接调用 audio_service_transfer()
→ 多业务时会产生资源竞争
```

**✅ 新方式：**
```
状态机统一调度：
  进入AI_STARTING → audio_service切换到AI模式
  进入VOICE_CALL  → audio_service切换到通话模式
  进入IDLE        → audio_service切换到唤醒模式
```

### 3. AI对话层职责简化

**只负责：**
- 接收PCM音频数据
- 调用coze_app发送语音
- 接收Coze回复音频
- 调用audio_service播放
- 向状态机报告事件

**不再负责：**
- ❌ Coze连接管理（移到service_starting阶段）
- ❌ 音频资源切换（移到状态机回调）
- ❌ 唤醒词控制（移到状态机回调）
- ❌ 状态转换决策（移到状态机）

## 🔀 典型场景流程

### 场景1：设备启动流程

```
1. app_main()
   ↓
2. 初始化状态机（BOOT状态）
   ↓
3. 启动Wi-Fi → EVENT_WIFI_CONNECTED
   ↓
4. 状态机：BOOT → NETWORK_CONNECTING
   ↓
5. 获取IP地址 → EVENT_NETWORK_READY
   ↓
6. 状态机：NETWORK_CONNECTING → SERVICE_STARTING
   → 回调：on_service_starting()
     - 初始化coze_app
     - 连接Coze（长连接）
     - 初始化ai_dialog
   ↓
7. Coze连接成功 → EVENT_SERVICE_READY
   ↓
8. 状态机：SERVICE_STARTING → IDLE
   → 回调：on_enter_idle()
     - 启动wake_word监听
     - 切换音频资源给wake_word
   ↓
9. 待机监听中...
```

### 场景2：正常AI对话

```
1. 待机状态（IDLE），用户："你好小飞"
   ↓
2. wake_word检测到唤醒词 → EVENT_WAKE_WORD_DETECTED
   ↓
3. 状态机：IDLE → AI_STARTING
   → 回调：on_ai_starting()
     - 停止wake_word
     - 切换音频资源给ai_dialog
     - ai_dialog_start_session()
     - coze_app_begin_turn(turn++)
     - 播放提示音
     - 发送EVENT_AI_READY
   ↓
4. 状态机：AI_STARTING → AI_LISTENING
   → 回调：on_ai_listening()
     - 开始采集用户语音并上传到Coze
   ↓
5. 用户说话中...Coze实时处理（服务端VAD）
   ↓
6. Coze判断用户说完 → 返回AI回复 → EVENT_AI_REPLY_START
   ↓
7. 状态机：AI_LISTENING → AI_PLAYING
   → 回调：on_ai_playing()
     - 播放AI回复音频
   ↓
8. 播放完成 → EVENT_AI_REPLY_END
   ↓
9. 状态机：AI_PLAYING → AI_LISTENING（继续等待用户）
   或者 Coze判断对话结束 → EVENT_CONVERSATION_ENDED
   ↓
10. 状态机：AI_LISTENING → IDLE
    → 回调：on_conversation_end()
      - ai_dialog_stop_session()
      - coze_app_end_turn()
      - 恢复唤醒词监听
```

### 场景3：对话中来电（高优先级打断）

```
1. AI对话中（AI_LISTENING）
   ↓
2. 后台推送来电 → EVENT_INCOMING_VOICE_CALL
   ↓
3. 状态机：AI_LISTENING → VOICE_CALL_INCOMING
   → 回调：on_voice_call_incoming()
     - 先停止ai_dialog
     - 结束coze_app轮次
     - 播放铃声
     - voice_call_ring("Unknown")
   ↓
4. 用户接听（或自动接听）→ EVENT_CALL_ACCEPTED
   ↓
5. 状态机：VOICE_CALL_INCOMING → VOICE_CALL_ACTIVE
   → 回调：on_voice_call_start()
     - voice_call_accept()
     - 切换音频资源给通话
     - 开始语音通话
   ↓
6. 通话中...
   ↓
7. 通话结束 → EVENT_CALL_ENDED
   ↓
8. 状态机：VOICE_CALL_ACTIVE → IDLE
   → 回调：on_voice_call_end()
     - voice_call_hangup()
     - 恢复唤醒词监听
```

### 场景4：通话中拒绝唤醒

```
1. 语音通话中（VOICE_CALL_ACTIVE）
   ↓
2. 用户说："你好小飞"（误触发）
   ↓
3. wake_word检测到唤醒词 → EVENT_WAKE_WORD_DETECTED
   ↓
4. 状态机查找转换表：
   VOICE_CALL_ACTIVE + EVENT_WAKE_WORD_DETECTED → 无匹配规则
   ↓
5. 记录日志：忽略唤醒词事件（通话优先）
   ↓
6. 保持通话状态，继续通话
```

## ✅ 架构优势

### 1. 资源无冲突
- 音频资源由状态机统一调度
- 避免多业务同时抢占资源
- 明确的资源所有权切换时机

### 2. 业务可扩展
- 新业务只需实现业务接口
- 在状态机中注册状态和事件
- 不影响现有业务逻辑

### 3. 优先级明确
- 通话 > AI对话 > 待机
- 来电可以打断AI对话
- 通话中自动拒绝唤醒词

### 4. 错误可恢复
- 网络断开自动进入恢复状态
- Coze错误自动重连
- 音频错误统一处理

### 5. 连接更稳定
- Coze保持后台长连接
- 不是每次唤醒建立连接
- 减少连接建立时间和失败率

### 6. 像手机系统
- 分层清晰，职责单一
- 状态机统一管理设备模式
- 应用层专注业务实现

## 📝 总结

本次架构重构实现了：

1. **完整的设备状态机**：13个状态，30+事件，支持优先级调度
2. **分层架构设计**：应用层/服务层/驱动层职责清晰

**架构特点：** 像手机操作系统一样，分层清晰，资源统一调度，业务独立扩展！
