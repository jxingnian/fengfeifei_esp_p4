## 🔄 状态转换流程

### 完整启动流程
```
BOOT
  ↓ [WiFi连接] EVENT_WIFI_CONNECTED
NETWORK_CONNECTING
  ↓ [获取IP] EVENT_NETWORK_READY
SERVICE_STARTING
  → 初始化coze_app
  → 连接Coze服务（长连接）
  → 初始化ai_dialog
  ↓ [Coze就绪] EVENT_SERVICE_READY
IDLE（待机）
  → 启动wake_word监听
  → 音频资源给wake_word
```

### AI对话流程
```
IDLE
  ↓ [检测到唤醒词] EVENT_WAKE_WORD_DETECTED
AI_STARTING
  → 停止wake_word
  → 音频资源切换给ai_dialog
  → ai_dialog_start_session()
  → coze_app_begin_turn(turn++)
  ↓ [AI就绪] EVENT_AI_READY
AI_LISTENING
  → 用户说话，实时上传到Coze
  ↓ [用户停止] EVENT_USER_STOPPED
AI_PROCESSING
  → 等待Coze回复
  ↓ [收到回复] EVENT_AI_REPLY_START
AI_PLAYING
  → 播放AI音频
  ↓ [播放完成] EVENT_AI_REPLY_END
AI_LISTENING（继续对话）或 IDLE（结束对话）
```

### 来电打断流程
```
AI_LISTENING（对话中）
  ↓ [来电] EVENT_INCOMING_VOICE_CALL
VOICE_CALL_INCOMING
  → 停止ai_dialog
  → 结束coze_app轮次
  → 播放铃声
  ↓ [接听] EVENT_CALL_ACCEPTED
VOICE_CALL_ACTIVE
  → 开始通话
  ↓ [挂断] EVENT_CALL_ENDED
IDLE
  → 恢复唤醒词监听
```

## 🎯 关键技术点

### 1. Coze连接生命周期分离
**核心改进：** 连接和会话分离

**旧方式：**
```c
唤醒 → coze_app_start() → 对话 → coze_app_stop()
     建立连接           断开连接
```

**新方式：**
```c
启动时: coze_app_connect()  // 建立长连接
唤醒时: coze_app_begin_turn()  // 开始会话
结束时: coze_app_end_turn()    // 结束会话（不断开连接）
断线时: coze_app_reconnect()   // 重连
```

### 2. 音频资源统一调度
**核心改进：** 状态机统一管理

```c
// 旧方式：各组件直接调用
wake_word.c: audio_service_transfer(...)
ai_dialog.c: audio_service_transfer(...)

// 新方式：状态机回调中统一调度
on_enter_idle():
    audio_service_transfer(AI_DIALOG, WAKE_WORD)

on_ai_starting():
    audio_service_transfer(WAKE_WORD, AI_DIALOG)

on_voice_call_start():
    audio_service_transfer(WAKE_WORD, VOICE_CALL)
```

### 3. 事件驱动架构
**核心改进：** 状态转换由事件驱动

```c
// 唤醒词检测
wake_word检测到 → device_state_send_event(EVENT_WAKE_WORD_DETECTED)
                → 状态机：IDLE → AI_STARTING

// AI回复
Coze音频到达 → emit_ai_event(AI_DIALOG_EVENT_AI_REPLY_START)
              → app_main → device_state_send_event(EVENT_AI_REPLY_START)
              → 状态机：AI_LISTENING → AI_PLAYING

// 来电打断
后台推送 → device_state_send_event(EVENT_INCOMING_VOICE_CALL)
        → 状态机：AI_LISTENING → VOICE_CALL_INCOMING
```
